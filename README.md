# OpenWorld City · Port Azure

原创单人浏览器城市沙盒。Three.js + TypeScript + Rapier + Vite，无登录、数据库或远程游戏后端。当前为程序化街区、授权 glTF 建筑 / 车辆 / 人物与 PBR 路面结合的可玩开发版本；不宣称达到 GTA 的画质、内容量或物理精度。

## 开发与部署

需要 Node.js 22.12+，推荐 pnpm 10。

```sh
pnpm install
pnpm dev
# 浏览器打开 http://127.0.0.1:5173
pnpm typecheck
pnpm test
pnpm build
pnpm preview
```

也可以使用 `npm run dev`、`npm run build` 等运行脚本。首次安装遇到网络问题时：

```sh
HTTPS_PROXY=http://127.0.0.1:8800 pnpm install
```

部署 `dist/` 到静态服务器即可。Worker 与脚本使用相对构建资源路径，无需后端；正式部署请使用 HTTPS。运行时仅向本站请求已打包资源；地图由 Seed 按需生成，不请求远程地图、字体或第三方素材服务。WebGL2 必需。

### GitHub Pages 自动发布

线上地址：[OpenWorld City](https://wl4g-games.github.io/mygta6/)。

[CI and GitHub Pages](.github/workflows/pages.yml) 在向 `main` 提交或更新 PR 时验证；合入 `main` 后自动发布同一份验证过的 `dist/`。验证包含单元／集成测试、素材校验、生产构建与 Chromium 实际进店，另外检查 Worker、压缩纹理解码、模型、贴图和三段手机视频的子路径加载。只有验证成功才部署。也可从 Actions 页面手动运行 `main` 分支的工作流。仓库 Settings → Pages 的 Source 应为 **GitHub Actions**。

构建时用 Vite `base` 设置部署路径，所有运行时素材也共享这个路径；本地开发继续使用 `/`。模拟本站部署：

```sh
pnpm build --base=/mygta6/
pnpm preview --base=/mygta6/ --port 4173
# 在另一终端运行：
CITY_PRODUCTION_URL=http://127.0.0.1:4173/mygta6/ pnpm test:production
```

首次运行浏览器验证前，执行 `pnpm exec playwright install chromium`。存档保存在浏览器本地；本机开发地址的存档不会自动迁移到线上域名。

## 已实现的开发版本功能

- 确定性 Seed 城区、全球对齐的连通道路和人行道、海湾、港口、工业区、郊区、连续坡道与跨海公路桥，可配置 16 × 16 km 逻辑坐标范围。
- Worker 按需生成；ACTIVE / NEAR / FAR / UNLOADED；方向与速度预测；有界并发、取消、超时、重试与去重；离开区域后卸载渲染和碰撞资源。
- 路面和关键建筑碰撞先于可通行状态准备；尚未具备物理覆盖时限制继续移动；低中高画质、动态像素比、实例化、资源共享和 GPU 内存估算。
- CC0 授权 glTF 骨骼人物与动画混合，保留独立的程序化备用形象；Rapier 胶囊控制器，步行、冲刺、跳跃、蹲姿、游泳、相机碰撞与两种视角。人物骨骼、衣物材质和资源租约独立管理。
- 11 类数据驱动车型，使用 CC0 glTF 车身、内饰与双级 LOD；车轮、前轮转向、制动灯、车门动画和骨骼驾驶员；自动夜间车灯、车况仪表与漆面磨损反馈。驾驶采用简化动态刚体，支持制动、倒车、燃油、碰撞损伤与服务修复。汽车店支持购买与车库提取，保留燃油、损伤、颜色和当前车型。
- 每个城市区块的 OPEN 沿街店铺有可实际穿过的门洞、室内家具、商品展示、店员、可开关冰箱、储物间与实体碰撞。其他大楼明确标注办公 / 住宅 / 关闭门面。
- 19 种数据驱动商店定义与一间可租赁住宅；首要商铺：便利店 (32,-27)、餐厅 (160,-27)、酒吧 (32,101)、燃油服务 (160,101)、汽车服务 (288,-27)。服务效果按店型配置，细节成熟度不同。银行、美发、咖啡馆、汽车店等按营业时间开关门；油泵、维修与洗车前场可通过实体路缘开口驶入。
- 便利店货架选货、收银台扣款、库存减少、背包增加、使用恢复、丢弃、半价卖回；现金和银行存取款；各店独立库存；事件驱动的交易与任务。选入购物篮的补给有手持模型。
- 复用 36 名行人、14 辆交通车与 10 辆停放车辆的有界对象池，行走、等待、受惊逃离与邻居对话；成年角色间非露骨的友好关系互动。餐厅 / 酒吧 / 咖啡馆有实体就座顾客与对话。
- NPC 受击、逃离、倒地；游戏化抢劫的不同店员结果和举手动画、通缉星级、实体警车沿路网响应、警员下车、A* 障碍绕行与进店追捕、搜寻、逃脱、罚款、医疗后果，通缉与装备状态可存档。
- 昼夜循环、太阳 / 月亮 / 星空、夜间路灯池与窗灯、晴 / 云 / 雨 / 雾 / 雷雨和湿润路面；中高画质包含半分辨率接触阴影。声音为本地合成的引擎、环境、脚步、雨声、雷声、喇叭、碰撞与交易提示；警笛使用随实际警车位置移动的 HRTF 空间声源。
- 主菜单、继续游戏、HUD、小地图、完整地图、基础路网 GPS、背包、商店、设置和性能面板。画质、音量和可重绑定键位会单独保存。
- 可重复社区接送：实体乘客等候、走到车旁上车、车内乘坐、途中存档、实际驾驶送达与报酬结算；可通过邻居或已购手机接单。
- PLAYTIME 店的 Harbor Lights 是原创 20 秒点击反应小游戏，按实际成绩结算一次游戏货币奖励。
- IndexedDB 本地存档、世界变化、库存、任务、车辆、角色状态、Seed 与 v1 / v2 / v3 到 v4 的版本迁移。每 30 秒和关键交易自动保存，F5 手动保存。

## 本轮可操作新增与修复

- 镜头：点击 3D 场景后移动鼠标，或用四个方向键控制上下左右；右键拖动也可用。驾驶时手动观察会暂缓自动回正。已修复墙面 / 楼板碰撞造成镜头无效坐标和灰屏的问题。
- 行人：物理位置与渲染位置分离，逐帧平滑位置和朝向；行走 / 站立有速度缓冲，避免碰撞时反复重启动画。
- 店门：新游戏出生点对准便利店门，E 打开实体门并沿短路径走入，仍由角色碰撞控制器移动；A / D / S 取消辅助。关门店铺仍受营业时间限制。
- NPC 车辆：靠近街上的交通车或停放车辆按 F 即可接管；有司机的车会使司机离车逃跑，盗车会报警。车型、车色和实体碰撞一起移交，交通池不会保留重叠的车身。
- SIGNAL 手机：先在电子商店购买（例如区块 `0,4`），P 打开手机；可向四名虚构联系人拨号、收发本地 NPC 消息，浏览三段原创城市视频、切换 / 暂停 / 点赞 / 评论；记录随 IndexedDB 存档保存。浏览器有本地语音时可播报通话台词。手机 UI 同步一个可见的 3D 手持设备。
- Azure Ride：手机“叫车”选择另一个街区的商店；预付游戏车费后，黄色 NPC 出租车驶至 GPS 路边候车点。靠近按 F 作为乘客上车，司机沿路网前往目的地，到达后按 F 下车。未上车取消可退款；乘车中按 F 可请求停车。与玩家自己开车接单的社区接送分开。
- CIVIC ATM：银行内两台、门外一台实体 ATM。正常使用 E 存取现金；面对机器用 Q / 装备攻击会报警，损毁后 E 拾取一次 $120。损伤、警报与现金领取状态会保存，反复进出不刷新钱。
- THE LOW TIDE（`0,1`，16:00–05:00）：实体两层室内、左侧可步行楼梯。一楼有驻唱、舞者、四名就座观众、可消费吧台及原创合成人声歌曲；可触发虚构抢劫与警察响应。二楼有穿正装的成年帮派角色、雪茄烟雾、文件 / 现金 / 手提箱交易场景，成年泳装护理员提供双方同意的肩部护理，并有可接近的 NPC 对话。无露骨性内容。

这些系统仍采用原型动作、邻域 AI 和有限对白。手机联络、社交内容与叫车均为单人游戏内部模拟，不连接真实社交网站、电话网络或 Uber 服务。

## 驾驶视角与会客区视觉修复

- 驾驶第一人称使用当前刚体的驾驶座变换，位置不经过第三人称的跟随平滑；转向时保留相对车身的转头角度。高速、刹车与短时左右转向均有浏览器回归覆盖。
- 第一人称保留真实骨骼模型的手臂和衣袖，过滤头部、兜帽与躯干；双手用手掌接触点握持会转动的方向盘，手指随握持姿势弯曲。打开手机后，右手留在方向盘，左手切换到手机。
- 已购买手机时，车内有可见的 GPS 屏；P 可打开可操作的手机并在实体屏幕播放同一视频。手机沿用菜单暂停规则。桥上与远海区域的目录查询也能正常使用。
- 二楼会客区按米制重新布置：扶手椅宽 1.05 m、坐垫高 0.46 m，成年角色身高约 1.78–1.86 m。加入办公桌、书柜、会客桌、文件、酒柜吧台、座凳、植物与分隔空间。
- Ari 的两件式泳装有独立的不透明服装几何，便装上衣与长裤隐藏；身体和腿部采用与原骨架相连的简化网格。肩部护理使用手掌朝向、稳定肘部方向及缓慢交替按压。
- 警员能使用同一实体楼梯到二楼，逮捕和近距离伤害均检查视线，避免隔着墙或楼板触发。

## 仍需完成 / 原型限制

- 人物与环境是合法授权的游戏资产和原创程序化模型的组合，并非最终写实美术；已加入手臂两关节 IK；尚无脚部地形 IK、复杂布料、扫描建筑或成熟的动作融合图。glTF 资源层支持 Meshopt 解码，但三套基础角色尚未压缩；车辆、建筑、街道设施及补充行人已使用 Meshopt + KTX2 / Basis 并通过浏览器加载。Draco 尚未接入。
- 驾驶为简化街机刚体模型，无独立车轮悬挂、轮胎求解、可变形车身和完整驾驶舱仪表。模型具有实际内饰与可动部件，驾驶参数仍需调校。
- 各店型使用有限但可进入的室内模板，包含床位、健身器材、理发椅、ATM、影院座椅与展车。租房可解锁一间实际可进入、可休息存档的住宅；手机有通话、消息、视频、叫车和 GPS；指南有商铺目录。影院是原创短片；装备库有四种游戏装备、弹匣、换弹、射线命中和发射器效果，仍缺少成熟动画、配件和完整战术系统。
- 警察、行人和车流是邻域原型 AI，并非覆盖整个城市的完整职业日程、语音、战术或群体导航。没有显式性行为内容。
- 当前基础道路仍为网格，加有 R1 公路、桥梁、连续坡道和港口码头；完整立交、收费站、隧道、地下停车场、机场、复杂港口、乡村地形和攀爬尚未完成。公园、山地及乡村尚未形成独立可玩区域。
- 已实现渲染浮动原点、室内可见性及屋顶管理、glTF 原型缓存、租约与对象池。物理仍使用 16 km 范围内的逻辑坐标；扩展更大范围时还需物理重定位。暂无 GPU 遮挡查询和完整 Portal 图。
- 天气与音场已有基础实现；实时玻璃 / 水面镜面反射、完整表演编舞和更丰富夜店活动仍需完善。水面为连续的程序波动与环境高光。
- 存档没有跨浏览器同步。清理站点存储会删除进度；关闭标签时异步保存仅作尽力补充，应以自动 / 手动保存为准。
- 16 km 是逻辑世界容量，不代表已手工制作 256 km² 的独特城区，也不代表全部验收指标已完成。性能必须以实际测试记录为准。

## 架构

`core/` 编排、输入和事件；`world/` 确定性生成、生命周期、调度和世界变化；`physics/` Rapier 生命周期；`assets/` 共享资源引用计数和实例化批次；`render/` 相机、灯光、天气和动态分辨率；`character/` 人物与可替换渲染模型；`vehicle/` 车辆；`interior/` 门面和室内工厂；`store/` 商店数据与邻域室内加载；`economy/` 原子交易；`npc/` 邻域生活；`missions/` 接送任务；`combat/` 装备与效果；`police/` 响应与徒步追捕；`persistence/` 版本化增量存档；`ui/` DOM 界面和地图；`audio/` 浏览器音频。

业务状态不依赖 Three.js 场景序列化。区块拥有实例矩阵、标牌纹理及静态碰撞体；资源管理器拥有共享几何和材质；店铺室内拥有家具、门和店员；卸载时按所有权释放。

## 测试

```sh
pnpm test                 # 确定性、经济、物理、存档迁移、加载生命周期
pnpm exec playwright install chromium  # 若本机尚无测试浏览器
pnpm test:e2e            # 实际键鼠可玩路径 + UI + 区域生命周期
pnpm test:stress         # 区域切换 / 回访与资源计数
```

端到端脚本的 `?e2e=1` 调试接口仅在 Vite 开发模式或显式 `--mode qa` 构建启用，生产包不暴露瞬移或调试修改入口。常规可玩路径通过键鼠操作；区域瞬移用例专门检测取消、卸载和回访生命周期。测试浏览器资源开销较高，默认单 worker。

## 固定构建验证与长测

```sh
pnpm exec vite build --mode qa --outDir artifacts/qa
pnpm exec vite preview --outDir artifacts/qa --port 4180
# 在另一个终端，使用同一份固定构建：
CITY_BASE_URL=http://127.0.0.1:4180 pnpm test:e2e
# 生产预览启动后，验证无 QA 接口并实际按 E 进入便利店：
CITY_PRODUCTION_URL=http://127.0.0.1:4173 node scripts/smoke-production.mjs
CITY_BASE_URL=http://127.0.0.1:4180 pnpm test:startup
CITY_BASE_URL=http://127.0.0.1:4180 CITY_SOAK_MINUTES=25 pnpm test:soak
```

若 Playwright 浏览器不在默认目录，可设置 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`。压力驾驶使用真实键盘输入、信号灯与障碍制动；测试开头用专用 QA 接口放置车辆，之后按实测位置运行。初始传输与压力数据输出到 `artifacts/`。性能 HUD 的内存数字是几何 / 纹理占用估算，未包含全部浏览器、物理、帧缓冲与驱动开销。测试结果与已发现问题见 [验证记录](docs/VALIDATION.md)。
